## Детальное описание gaps

### GAP-01: Business Layer — Отсутствие процесса персонализации

**Baseline:**
- Предложения формируются по общим правилам
- Нет процесса использования данных для персонализации
- Маркетинговые кампании не таргетированы на сегменты

**Target:**
- Процесс персонализации на основе клиентских сегментов
- Автоматическая генерация предложений на основе единого профиля
- Измерение эффективности персонализации

**Формулировка:**
Отсутствует бизнес-процесс персонализации предложений, который бы использовал данные из CDP и аналитической платформы для формирования индивидуальных предложений клиентам.

**Связанное requirement:**
«Увеличить повторные продажи за счёт персональных предложений»

**Work package:**
WP-01: Разработка и внедрение процесса персонализации предложений

**Приоритет: Высокий**
Без процесса персонализации цель увеличения повторных продаж не будет достигнута, даже если все технические компоненты будут внедрены.

---

### GAP-02: Data Layer — Разрозненность данных клиентов

**Baseline:**
- Данные клиентов хранятся в CRM (история взаимодействий)
- Данные о транзакциях в POS
- Данные об онлайн-поведении в интернет-магазине
- Нет единого представления о клиенте
- Согласия клиентов не централизованы

**Target:**
- Единый профиль клиента в CDP
- Клиентские сегменты из аналитической платформы
- Централизованное хранение согласий
- Единая модель данных о клиенте

**Формулировка:**
Данные клиентов фрагментированы между тремя системами (CRM, POS, интернет-магазин), что делает невозможным формирование единого профиля и персонализацию предложений.

**Связанное requirement:**
«Формировать единый профиль клиента»; «Учитывать согласия клиентов»

**Work package:**
WP-02: Консолидация данных клиентов и разработка единой модели данных

**Приоритет: Критический**
Это фундаментальный gap — без единого профиля клиента все остальные инициативы теряют смысл.

---

### GAP-03: Application Layer — Отсутствие CDP и аналитической платформы

**Baseline:**
- CRM: управление взаимоотношениями с клиентами
- POS: обработка транзакций
- Интернет-магазин: онлайн-продажи
- Нет системы для консолидации данных
- Нет системы для сегментации
- Нет API для интеграции

**Target:**
- CDP: формирование единого профиля клиента
- Аналитическая платформа: расчёт клиентских сегментов
- API: интеграция между системами

**Формулировка:**
Отсутствуют ключевые приложения target architecture: CDP для консолидации данных и аналитическая платформа для сегментации клиентов.

**Связанное requirement:**
«Интеграция должна выполняться через API»

**Work package:**
WP-03: Внедрение CDP
WP-04: Внедрение аналитической платформы
WP-07: Разработка API для интеграции

**Приоритет: Критический**
Это ядро target architecture — без CDP и аналитической платформы персонализация невозможна.

---

### GAP-04: Technology Layer — Отсутствие инфраструктуры для новых компонентов

**Baseline:**
- Инфраструктура поддерживает существующие системы (CRM, POS, интернет-магазин)
- Нет выделенных ресурсов для CDP и аналитики

**Target:**
- Серверы/облако для CDP
- Вычислительные ресурсы для аналитической платформы
- Хранилище данных для единого профиля
- Сетевая инфраструктура для API

**Формулировка:**
Отсутствует технологическая инфраструктура для размещения и работы новых компонентов (CDP и аналитической платформы).

**Связанное requirement:**
Не определено явно (неявный gap)

**Work package:**
WP-05: Подготовка технологической инфраструктуры

**Приоритет: Средний**
Должен быть решён до или параллельно с внедрением CDP, но не является бизнес-критичным сам по себе.

---

### GAP-05: Governance Layer — Отсутствие механизма управления согласиями

**Baseline:**
- Согласия клиентов собираются, но не централизованы
- Нет системного механизма проверки согласий при обработке данных
- Риск нарушения GDPR/законодательства о персональных данных

**Target:**
- Централизованное хранение согласий
- Автоматическая проверка согласий при персонализации
- Механизм отзыва согласий
- Аудит использования данных

**Формулировка:**
Отсутствует механизм управления согласиями клиентов (Consent Management), что создаёт юридические риски и нарушает требование юридического отдела.

**Связанное requirement:**
«Юридический отдел требует учитывать согласия клиентов»

**Work package:**
WP-06: Внедрение системы управления согласиями (Consent Management Platform)

**Приоритет: Высокий**
Юридическое требование с риском штрафов и репутационных потерь. Должно быть реализовано до запуска персонализации.

## Диаграмма зависимостей work packages

```
WP-02 (Консолидация данных) ──► WP-03 (Внедрение CDP)
WP-05 (Инфраструктура) ──► WP-03 (Внедрение CDP)
WP-03 (Внедрение CDP) ──► WP-04 (Аналитическая платформа)
WP-06 (Consent Management) ──► WP-01 (Процесс персонализации)
WP-04 (Аналитическая платформа) ──► WP-01 (Процесс персонализации)
WP-07 (API) ──► WP-03, WP-04
```

**Рекомендуемый порядок реализации:**
1. WP-02 + WP-05 + WP-06 (параллельно)
2. WP-03 + WP-07
3. WP-04
4. WP-01

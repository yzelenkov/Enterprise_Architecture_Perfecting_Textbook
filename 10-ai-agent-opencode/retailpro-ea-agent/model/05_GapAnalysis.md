## 2. Детальное описание gaps

### GAP-01: Business — Отсутствует автоматическая сегментация
**Baseline:** Процесс `bp_segment_manual` ("Формировать сегменты клиентов") выполняется актером `ba_marketers` (маркетологи) вручную в `app_excel` (Excel, R-04 Rel_Serving). Объект `bo_client_segment` читается/формируется процессом (R-03).
**Target:** Сервис `as_segmentation` ("Автоматическая сегментация клиентов") реализуется платформой `app_analytics` (R-11) и обслуживает процесс `bp_segment_manual` (R-13, To-be).
**Gap:** В As-is нет автоматической сегментации; сегменты формируются вручную в Excel. В To-be сегментация должна быть автоматизирована через аналитическую платформу. Разрыв — отсутствие автоматизации, что напрямую снижает скорость и качество персональных предложений.
**Приоритет:** High — без автоматизации сегментации цель персонализированных предложений не достижима в требуемых темпах.

### GAP-02: Business — Отсутствует бизнес-сервис персональных предложений
**Baseline:** Бизнес-сервис `bs_personalized_offers` ("Персональные предложения клиентам") отсутствует в As-is (состояние To-be, висячий элемент без связей).
**Target:** `bs_personalized_offers` присутствует в To-be, связана с целью `goal_repeat_sales` через способность `cap_personalization` (R-12).
**Gap:** Нет бизнес-сервиса, который бы доставлял персональные предложения клиентам. Это разрыв между текущей операционной моделью и целевой.
**Приоритет:** High — это ключевая цель бизнеса (увеличить повторные продажи за счет персональных предложений); без сервиса цель не достижима.

### GAP-03: Data — Отсутствует единый профиль клиента
**Baseline:** `data_client_data` ("Данные о клиентах") доступен раздельно в `app_crm` (R-05), `app_pos` (R-06) и `app_eshop` (R-07). Оценка `ass_client_data` фиксирует разрозненность.
**Target:** Данные консолидируются в `app_cdp` (CDP) через потоки от POS (R-08) и интернет-магазина (R-09).
**Gap:** Единого профиля клиента нет; данные разрознены между тремя системами, что затрудняет сегментацию и персонализацию.
**Приоритет:** High — блокирует остальные gaps: без единого профиля невозможны корректная сегментация и персональные предложения.

### GAP-04: Data — Согласия клиентов не синхронизированы
**Baseline:** Оценка `ass_consent_sync` ("Согласия клиентов не синхронизированы"). Данные `data_client_consent` ("Согласия клиентов") существуют как объект данных, но связей с системами нет (висячий элемент).
**Target:** Согласия синхронизированы и учитываются при формировании профилей в CDP.
**Gap:** Согласия клиентов не синхронизированы между системами; нет механизма учета согласий при обработке данных.
**Приоритет:** High — нарушение ограничения (закон о персональных данных); CDP не может использовать данные клиентов без подтвержденных согласий.

### GAP-05: Application — Отсутствует CDP
**Baseline:** Компонент `app_cdp` (CDP) имеет состояние только To-be ("планирует внедрить CDP"). В As-is отсутствует.
**Target:** `app_cdp` внедрен, включает интерфейс `ai_customer_api` (R-10 Rel_Composition), принимает данные от POS и интернет-магазина (R-08, R-09).
**Gap:** Отсутствует CDP для создания единого профиля клиента.
**Приоритет:** High — блокирует интеграцию POS/интернет-магазина и аналитику; без CDP единый профиль невозможен.

### GAP-06: Application — Отсутствует Customer API
**Baseline:** Интерфейс `ai_customer_api` (Customer API) имеет состояние только To-be ("создать Customer API"). В As-is отсутствует.
**Target:** `ai_customer_api` входит в состав CDP (R-10 Rel_Composition) и обеспечивает доступ к данным клиентов.
**Gap:** Нет Customer API для программного доступа к данным клиентов со стороны аналитики и каналов сбыта.
**Приоритет:** High — необходим для доступа аналитической платформы и других потребителей к данным из CDP.

### GAP-07: Application — POS и интернет-магазин не интегрированы с CDP
**Baseline:** `app_pos` и `app_eshop` работают с `data_client_data` изолированно (R-06, R-07 Rel_Access_rw). Потоков данных в CDP нет (R-08, R-09 только To-be).
**Target:** POS и интернет-магазин передают данные клиента в CDP (R-08, R-09 Rel_Flow_Down).
**Gap:** Каналы сбыта не интегрированы с CDP; данные о клиентах не поступают в единый профиль в момент взаимодействия.
**Приоритет:** High — без интеграции данные не попадают в CDP, единый профиль не формируется и не обновляется.

### GAP-08: Application — Отсутствует аналитическая платформа
**Baseline:** Компонент `app_analytics` (Аналитическая платформа) имеет состояние только To-be. В As-is отсутствует.
**Target:** `app_analytics` внедрена и реализует сервис `as_segmentation` (R-11 Rel_Realization).
**Gap:** Нет аналитической платформы для автоматической сегментации клиентов.
**Приоритет:** Medium — снижает эффективность сегментации, но цель достижима вручную на переходном этапе (до внедрения платформы).

### GAP-09: Application — Excel как инструмент сегментации подлежит замене
**Baseline:** `app_excel` (Excel) обслуживает процесс `bp_segment_manual` (R-04 Rel_Serving). Классификация неточна (приложение или инструмент конечного пользователя — спорно).
**Target:** Excel заменен на автоматическую сегментацию через `app_analytics` / `as_segmentation`.
**Gap:** В As-is сегментация зависит от Excel; в To-be этот инструмент должен быть выведен из эксплуатации.
**Приоритет:** Medium — ручная работа в Excel снижает эффективность, но цель достижима; замена связана с GAP-01 и GAP-08.

### GAP-10: Governance — Не обеспечен учет согласий клиентов
**Baseline:** Нет элемента управления согласиями (политики, роли, соответствие закону). Оценка `ass_consent_sync` фиксирует проблему. Данные `data_client_consent` без связей.
**Target:** Учет согласий клиентов обеспечен при обработке персональных данных в CDP (связано с GAP-04).
**Gap:** Отсутствует механизм учета и проверки согласий клиентов при формировании профилей и сегментов.
**Приоритет:** High — нарушение ограничения (закон о персональных данных); внедрение CDP без учета согласий создает правовые риски.

## 4. Спорные решения

- Все требования (`req_*`) выведены неявно из текста `input/retailpro_case.md`, а не взяты из объявленных элементов модели. В `01_Elements.md` нет `Motivation_Requirement`. Каждый gap помечен "требует проверки архитектором" в колонке требований. Требуется утверждение формального списка требований архитектором.
- `app_excel` классифицирован как `Application_Component`, но может быть инструментом конечного пользователя (уверенность low в `01_Elements.md`). GAP-09 зависит от этой классификации.
- `bs_personalized_offers` — висячий элемент в To-be, связь не описана в `02_Relationships.md`. GAP-02 опирается на косвенный вывод из цели.
- `data_client_consent` — висячий элемент без связей. GAP-04 и GAP-10 опираются на оценку `ass_consent_sync`, а не на отношения данных.
- `cap_personalization` выведен косвенно из фразы "персональные предложения" (уверенность medium). Используется в GAP-02.
- Слой Technology пуст — технологические gaps не выявлены по правилу навыка (создавать только при наличии технологических элементов). Неявный технологический gap (инфраструктура для CDP) не оформлен, требует проверки архитектором.
- Приоритеты назначены качественно по правилам навыка (High/Medium/Low), количественных данных (сроки, бюджет) в документах нет.

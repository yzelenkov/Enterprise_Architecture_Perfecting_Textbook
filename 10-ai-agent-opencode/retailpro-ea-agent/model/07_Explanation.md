# Пояснение к диаграмме прикладной архитектуры RetailPro (To-be) для аудитории IT

Диаграмма `diagrams/retailpro_application_tobe.puml` описывает целевое состояние (To-be) прикладного слоя архитектуры RetailPro: набор приложений, интерфейсов, потоков данных и зависимостей. Состав элементов и отношений берётся из model/01_Elements.md и model/02_Relationships.md; диаграмма прошла проверку `archimate_check` со статусом PASS (0 ошибок, 0 предупреждений, см. model/03_PlantUML.md и model/04_Review.md). Новых элементов, отсутствующих в модели, здесь нет.

Аббревиатуры: CDP — Customer Data Platform (платформа данных клиентов), API — application programming interface (программный интерфейс приложения).

## 1. Приложения

|---|---|---|---|
| CDP (app_cdp) | Application_Component | To-be | Компонент целевого состояния; планируется внедрить для создания единого профиля клиента (связано с GAP-03, GAP-05 в model/05_GapAnalysis.md). |

## 2. Интерфейсы

- Customer API (ai_customer_api) — Application_Interface, состояние To-be. Является частью композиции CDP (Rel_Composition, R-10). По модели предназначен для создания точки доступа к данным клиентов ("создать Customer API"). Потребители этого интерфейса на этой диаграмме не изображены.

## 4. Зависимости

- **Композиция:** CDP (app_cdp) → Customer API (ai_customer_api), Rel_Composition (R-10), уверенность medium. Интерфейс входит в состав компонента CDP.
- **Реализация:** Аналитическая платформа (app_analytics) → сервис "Автоматическая сегментация клиентов" (as_segmentation), Rel_Realization (R-11), уверенность high.
- **Serving:** сервис "Автоматическая сегментация клиентов" (as_segmentation) → бизнес-процесс "Формировать сегменты клиентов" (bp_segment_manual), Rel_Serving (R-13), подпись "автоматическая сегментация", уверенность medium. Это единственная связь из прикладного слоя к бизнес-процессу на диаграмме.

## 5. Миграция (переход As-is → To-be)

- **Остаются без изменений (As-is, повторены в To-be):** POS (app_pos), Интернет-магазин (app_eshop), бизнес-процесс "Формировать сегменты клиентов" (bp_segment_manual) — единственный бизнес-элемент на прикладной диаграмме To-be.
- **Внедряются (состояние To-be):** CDP (app_cdp), Customer API (ai_customer_api), Аналитическая платформа (app_analytics), Автоматическая сегментация клиентов (as_segmentation).
- **Порядок переходов (из model/06_MigrationRoadmap.md):** сначала синхронизация и учёт согласий клиентов (WP-04), затем внедрение CDP (WP-03) и создание Customer API (WP-05), затем интеграция POS и интернет-магазина с CDP (WP-06), затем аналитическая платформа (WP-07) и автоматизация сегментации (WP-01), в конце — бизнес-сервис персональных предложений (WP-02).
- **Критический путь:** WP-04 → WP-03 → WP-06 → WP-07 → WP-01 → WP-02.
- Сроки, бюджет и трудозатраты в документах не указаны — не оценено.

## 6. Технические риски

- R-08 и R-09: уверенность low; подпись "данные клиента" не уточнена в тексте — при реализации интеграции требуется уточнение состава и формата передаваемых данных.
- R-13: связь сервиса сегментации и бизнес-процесса выведена косвенно, уверенность medium.
- app_excel не входит в эту диаграмму, но в модели классифицирован как Application_Component с низкой уверенностью (может быть инструментом конечного пользователя) — влияет на замену Excel в процессе сегментации (GAP-09, WP-01).
- data_client_consent — висячий элемент без связей в модели (не входит в эту диаграмму) — учёт согласий клиентов не привязан к конкретным системам.
- В модели отсутствуют технологические элементы (слой Technology пуст) — технологические требования к инфраструктуре CDP не описаны (неявный gap этапа 5).
- Переход маркетологов с ручной сегментации в Excel на автоматическую — организационный риск пакета WP-01.
